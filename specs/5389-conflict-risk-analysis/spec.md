# Spike #5389: is `git merge-tree` enough to advise a lane? (epic #5388)

**Decision: build, with the platform tool.** One script wraps `git merge-tree --write-tree --name-only` of the lane's head against `origin/main` and every open PR head, and gives one advice per PR: go, wait for #N, or stack on #N. No other layer yet. The advice is advisory, never a gate.

## Replay: our data (14 Nov 2026)

Method (scratch script, not committed): the last 120 merged PRs (#5168–#5444). For each PR, its *first form* is the head before its first force-push (its head when never force-pushed). A pair is concurrent when the later-merged PR B was open when the earlier-merged PR A landed: 575 pairs. Predicted: `merge-tree(A first form, B first form)`. Actual: B's first form conflicts with main right after A landed but did not right before it (A caused it). Conflicts B already had with main, or A with main, are taken out of the prediction ("pair-only").

| Measure | Result |
|---|---|
| PRs force-pushed at least once | 23 of 120 |
| Concurrent pairs | 575 |
| Pairs with a file in common | 95 |
| Pairs `merge-tree` says conflict, raw | 161 (137 once generated files are dropped) |
| Same, pair-only (minus conflicts each PR already has with main) | 50 (44 not generated) |
| Actual one-step conflicts caused by A landing | 15 pairs, 10 distinct PRs |
| Pair-only prediction vs actual | 11 hit, 39 over-warn, 4 missed |
| A file in common as predictor | 15 hit, 80 over-warn, 0 missed |

Reading:

1. **Raw `merge-tree` is too noisy:** a stale or long-lived PR (#5406, `Web/src/app.css`; #5391) conflicts with all of main and so with every pair. The tool must report **per PR: conflict with main** first, and count a pair only for files that do not already conflict with main.
2. **Pair-only recall is 11 of 15 (73%); precision is about 22%.** The four misses were chains (a third PR changed the same file, e.g. `citimings_test.go`, `integrations.md`) or a stale first form. The over-warns are conflicts that vanished because B rebased or A changed again before landing, or git conflicted where a person would not. So: enough to advise, not enough to gate.
3. **A file in common finds the same conflicts but warns 80 times,** `merge-tree` halves that and names the hunk's files.
4. **Generated files are about a third of conflicting file mentions** (120 of 354 raw: `generated.ts`, `Go/wire/*_gen.go`, `Packages/Wire/*.json`, token CSS, `docs/reference/*`, parity files, `Package.resolved`). Wire schema JSON and `docs/reference/integrations.md` are not regenerated by one command everywhere: treat `*_gen.go`, `generated.ts`, `tokens.css`, `Package.resolved`, `go.sum` as "regenerates" (not counted), and the rest as counted. Hot counted files: `Web/src/app.css`, `Go/internal/agentsd/citimings*.go`, `Web/src/route.ts`, `docs/reference/integrations.md`.
5. **Cost:** 575 pairs in 90 s on a blobless clone, mostly blob fetches; one lane against about 10 open PRs is a few seconds with a warm repo. No worktree is needed (`merge-tree` writes objects, not files).

So the exact check is enough for the first version. Add layers (hunk overlap, symbol overlap, churn weight) only if lanes still hit conflicts the report said "go" for.

## Prior art, one line each

- **Clash** (clash-sh/clash, MIT, pushed 2026-07-17, 66 stars): a Rust CLI that does this over local git worktrees for parallel agents, with `git merge-tree` underneath. It knows worktrees, not open PRs, and has no go/wait/stack advice. Fit: a model to copy, not a dependency (a Rust binary for one `git` call).
- **GitHub mergeability API** (`mergeable` / `mergeStateStatus`, platform): one PR against its base only, never PR against PR; lags a push. Fit: no; we already use it after the fact (#5321).
- **Mergify merge queue** (proprietary service) and **Graphite** (proprietary): stack and speculative-merge queues; they order PRs, they do not warn a lane before it writes. Fit: our stacking rule (#1777) already does this by hand. Licences and release dates from memory, not re-checked.
- `git merge-tree --write-tree` (git 2.38+, GPL-2.0 platform tool, in the Git we ship): the primitive. Fit: use it.

## Advice rules

Inputs per open PR P: `conflicts_main(P)`, `pair_files = merge-tree(lane, P) − conflicts_main(lane) − conflicts_main(P) − regenerating files`, `lines(P)` (additions + deletions), `lands_soon(P)` (checks green and auto-merge on, or label `approved`), `base(P)` (main, or another lane branch).

Per PR:

1. `pair_files` empty → **go** for that PR.
2. `pair_files` non-empty and `lands_soon(P)` → **wait for #P**: it lands in minutes and the lane rebases once on a clean base. (A lane that has not started waits; a lane that has pushed rebases after P lands.)
3. `pair_files` non-empty, P not near landing (red or no checks, `needs-approval` and waiting for Alex, or stale more than 24 h) and the lane's change **builds on** P's (the lane's head contains P's commits, or the lead says it depends on it) → **stack on #P**: base the branch on P's branch, no auto-merge until P lands (#1777).
4. `pair_files` non-empty, not near landing, no dependence → **go**, with a note naming the files, since P's order is not known. Small overlap (at most 3 files and at most 40 changed lines in both) never says wait.
5. The overall advice is the strongest of the per-PR ones: `stack` over `wait` over `go`; with several `wait`, wait for the latest-landing one. A cycle (P waits for the lane's own PR) is `go`.
6. The lane's own conflict with main (`conflicts_main(lane)`) is shown as "rebase now", never as wait.

## Report JSON (draft)

```json
{
  "version": 1,
  "head": "<sha of the lane or working tree>",
  "main": "<sha of origin/main>",
  "main_conflicts": ["Web/src/app.css"],
  "advice": "wait",
  "advice_for": 5420,
  "prs": [
    {
      "number": 5420,
      "head": "<sha>",
      "base": "main",
      "state": "conflict",
      "files": ["Web/src/app.css"],
      "ignored": ["Web/src/protocol/generated.ts"],
      "lines": 571,
      "lands_soon": true,
      "advice": "wait"
    }
  ]
}
```

`state` is `clean`, `conflict` or `error`. Exit code 0 for any advice (advisory); non-zero only for an error. `--json` prints this; the default prints one line per PR and the overall advice.

## Child for the lead to file (one)

**`scripts/conflict-risk.sh <branch|--worktree>` (task, size M, `feature:parallel-lanes`):** Python or shell, `git merge-tree` and `gh pr list --json number,headRefOid,baseRefName,files,statusCheckRollup,autoMergeRequest,labels`; fetches `refs/pull/*/head` for open PRs; takes a working tree by committing it to a temporary object (`git stash create`); applies the advice rules and report above; tests on a scratch repo with a conflicting pair, a stale PR and a regenerating file; mentions it in the lane and lead skills (run before the first push and before auto-merge; a lead runs it on a child's branch). Replaces the exact-check half of the idea; the later layers are not filed until a lane hits a conflict the report called "go".
